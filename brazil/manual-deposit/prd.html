1. 背景与目标

本需求围绕商户财务管理下的人工提存能力进行原型化补充，覆盖人工单笔存入、人工单笔提出、人工优惠、批量人工优惠、人工提存记录、人工优惠记录、客户端站内信与领取弹窗交互，并补充系统管理 / 安全设置中的金额上限配置。

目标是让运营人员在人工资金调整和优惠派发场景中，先校验会员信息，再按明确配置保存或执行，并让资金账变、优惠派发、玩家领取和记录流转路径清晰可追溯。

  • 还原截图中的后台视觉和操作路径，作为评审与研发对齐基准。
  • 明确单笔操作的会员 ID 校验、保存二次确认、成功/失败提示。
  • 补齐人工优惠与批量人工优惠的领取方式、奖励加倍、模板管理、状态流转、查看会员、记录查询和客户端领取反馈。
  • 本期不做自动优惠、自动优惠统计，对应 tab 在原型中直接移除。

2. 范围说明

范围类型 内容
本期包含 人工存入、人工提出、人工优惠、批量人工优惠、人工优惠记录、人工提存记录中的人工存款记录/人工提款记录/优惠赠送记录，客户端站内信/领取弹窗/加倍充值交互，以及系统管理 / 安全设置金额配置更新。
本期不包含 自动优惠、自动优惠统计；未截图后台页面不扩展。
演示数据 正确会员 ID 使用 123456 进行原型演示；成功搜索后展示会员信息。
菜单提示 左侧菜单“人工提存”“人工提存记录”展示调整标志，提示涉及本次需求调整。

4. 通用交互规则

规则 说明
会员 ID 校验 人工存入、人工提出、人工优惠等单笔操作必须先点击会员 ID 搜索按钮。只有成功读出会员信息后才允许保存。
正确 ID 演示 输入 123456 并点击搜索，展示账号类型、账号、所属地区、所属商户、会员余额、会员等级。
保存二次确认 点击保存后弹出确认框，例如“确认人工存入?”，确认后再执行保存。
后台金额上限 人工存入、人工优惠、批量人工优惠金额受系统管理 / 安全设置中的后台配置限制；人工存入金额不能大于“人工存入单笔金额”，人工优惠金额不能大于“人工优惠单笔金额”，批量人工优惠金额不能大于“批量人工优惠单笔金额”。人工提出本期不做单笔上限校验，仅校验金额必填且大于0。原型示例配置：人工存入单笔金额1001，人工优惠单笔金额100，批量人工优惠单笔金额100。
列表作废 点击作废弹出二次确认；确认后提示“作废成功”，当前行操作状态由“准备”改为“作废”，并隐藏该行作废按钮。
字段间距 列表中长订单号、操作状态、订单状态等字段需保留独立列宽，避免文本挤压或贴合。
赠送对象命名 所有列表中的“首存次日未充值用户”统一调整为“批量导入”。

4.2 客户端交互页

模块/场景 需求说明
入口 原型新增“客户端交互”页签，作为评审演示页；不代表后台真实菜单必须新增该入口。
客户端首页 展示玩家端首页内容，并作为人工优惠弹窗领取的承载页面。
个人中心 展示会员信息、余额、充值/提现按钮和站内信入口；站内信红点数量随演示场景变化。
消息中心 Notificação tab 展示站内信列表，点击消息卡片进入详情页。
人工存入通知 人工存入成功后新增站内信：标题 Notificação de Depósito Bem-sucedida；正文 Seu depósito foi bem-sucedido, 1,01 foi creditado em sua conta,dos quais 0,01 é o valor do desconto de depósito。
人工提出通知 人工提出成功且后台选择发送站内信时新增站内信：标题 Notificação de Dedução Manual；正文 Sua conta foi deduzida em {扣款金额}, por favor, note a mudança no saldo。扣款金额按后台人工提出实际金额展示。
优惠领取成功通知 所有人工优惠或批量人工优惠遵从“领取成功才发站内信”的原则。玩家成功领取初始奖励后发送一次同一模板站内信：标题 Notificação de Ofertas de Manuais；正文 [Ofertas de Manuais] Recompensa: {实际发放金额} foi emitida, por favor, note a mudança no saldo。若开启奖励加倍，初始奖励领取成功发一次；玩家完成加倍条件并成功领取加倍奖励后，再发送一次同模板站内信。金额由后台配置的优惠金额、加倍结果或实际领取结果动态传入，不是客户端固定值。
自动领取优惠 后台配置自动领取时，客户端不展示领取弹窗；自动领取视为后台直接领取成功，领取成功后新增优惠站内信。
弹窗领取-不开启奖励加倍 玩家进入客户端首页时展示领取弹窗，内容金额按后台配置的优惠金额动态展示，例如 Receber um bônus +R${配置金额}；点击 RECEBER 后领取成功并发送优惠领取成功站内信；客户端不自动跳转消息中心，玩家可自行从站内信入口查看。
弹窗领取-按充值金额固定倍数 先展示初始奖励领取弹窗；点击 RECEBER 后初始奖励领取成功并发送一次站内信，但不自动跳转消息中心，随后展示 Multiplier Rewards 加倍提示。提示内按后台加倍模板展示充值金额档位与固定倍数，例如“Depósito / múltiplo”两列；档位金额和倍数均由后台配置动态传入。玩家继续充值并成功领取加倍奖励后，再发送一次优惠站内信。
弹窗领取-按充值金额随机倍数 流程与固定倍数一致，但 Multiplier Rewards 中每个充值金额档位展示最小/最大随机倍数范围，例如“1,10 - 3x”；最终加倍倍数以后端实际计算结果为准。玩家成功领取加倍奖励后，再发送一次优惠站内信。
充值后领取 客户端首页展示充值后领取弹窗，包含初始奖励金额、活动说明、充值条件金额、Depositar Agora、Desistir。金额与充值条件由后台配置传入；点击 Depositar Agora 进入充值页，点击 Desistir 关闭弹窗并视为放弃。完成充值条件后不直接发站内信，而是展示可领取状态；玩家点击 RECEBER 领取成功后才生成优惠站内信，且不自动跳转消息中心。
加倍提示 加倍提示提供 Continue reivindicando 与 Coletar Bônus Multiplicado 两个按钮；金额档位、倍率或倍率范围由后台配置动态传入，不是客户端固定值。
放弃加倍 点击 Continue reivindicando 关闭加倍提示，仅保留初始奖励领取结果，不产生加倍奖励站内信。
继续加倍 点击 Coletar Bônus Multiplicado 进入充值页；充值满足加倍条件金额并成功领取加倍奖励后，发放第二条优惠领取成功站内信，金额按加倍后金额展示；充值成功后不强制跳转消息中心。
充值页 展示 pix-1 / pix-2、充值金额输入、快捷金额和 Depositar Agora 按钮；原型用于演示满足加倍条件后的消息流转。

5. 人工存入

模块 需求说明
字段 会员ID、存入金额、赠送比例、打码量、充值提现倍数、优惠提现倍数、备注、保存。
打码量默认 默认时展示“充值提现倍数”“优惠提现倍数”。计算方式：存入金额×充值提现倍数 + 赠送优惠×优惠提现倍数。
打码量自定义 自定义时展示出款所需流水输入框，流水达到输入值即可出款。
提示 存入金额 tooltip：不能大于后台配置的人工存入单笔金额；赠送比例 tooltip：存入金额加入赠送比例的优惠。
校验 未正确搜索会员时不允许保存；存入金额必填且必须大于0，并且不能大于后台配置的人工存入单笔金额。
账变与记录 创建成功后直接完成账变，并在人工提存记录的人工存款记录中展示。若包含赠送优惠，优惠部分按领取状态进入优惠赠送记录。

6. 人工提出

模块 需求说明
字段 会员ID、提现金额、备注、邮件通知、保存。
邮件通知 单选项：发送邮件通知、不发送邮件通知，默认发送邮件通知；邮件通知即客户端站内信通知。
会员信息 搜索成功后下方展示账号类型、账号、所属地区、所属商户、会员余额、会员等级。
保存 点击保存需先通过会员 ID 校验，且提现金额必填、大于0，再弹出二次确认。
金额校验 人工提出本期不做单笔上限校验，不读取安全设置页单笔金额上限；仅校验提现金额必填且必须大于0。
账变与记录 创建成功后直接完成扣款账变，并在人工提存记录的人工提款记录中展示。

7. 人工优惠

模块 需求说明
基础字段 会员ID、存入金额、打码量、优惠提现倍数或出款所需流水、备注、APP端备注、领取方式、保存。
领取方式 单选项：自动领取、弹窗领取、充值后领取。批量人工优惠及相关弹窗中的领取方式交互需与人工优惠保持一致。
金额校验 存入金额必填且必须大于0，并且不能大于后台配置的人工优惠单笔金额。
自动领取 无额外执行条件，保存后直接到账；人工优惠记录生成一条已完成、已领取订单，同时流入人工提存记录的优惠赠送记录。
弹窗领取 展示奖励过期时间、奖励加倍、加倍方式、加倍倍数/模板、稽核倍数、稽核平台；创建后先在人工优惠记录生成未领取订单，只有玩家成功领取后才流入优惠赠送记录。
充值后领取 展示充值条件、充值金额、奖励过期时间，充值条件包含单笔充值和累计充值；创建后先在人工优惠记录生成未领取订单，满足条件并领取成功后才流入优惠赠送记录。
指定平台 奖励加倍稽核平台选择“指定平台”时展示平台选择器，含电子/体育 tab、全部平台、POPOK、YELLOWBAT、PLAYNGO 等平台行。

8. 加倍模板管理

场景 需求说明
添加模板入口 在人工优惠弹窗领取且加倍方式为按充值金额加倍时，点击“添加模板”打开“添加加倍模板”列表弹窗。
模板列表 列包含创建时间、模板名称、加倍类型、操作人、操作；支持新增、编辑、删除。
新增模板 字段包含模板名称、加倍类型、充值金额、加倍倍数；加倍类型包含按充值金额固定倍数、按充值金额随机倍数。
随机倍数 选择按充值金额随机倍数后，每行展示充值金额、最小加倍倍数、最大加倍倍数、期望倍数、加行、减行。
删除确认 删除模板弹窗提示：确认删除该模板？使用中的模板被删除系统会自动切换至默认模板。
查看模板 记录列表或查看会员弹窗中的加倍方案链接打开只读“查看模板”弹窗；无加倍方案使用“-”填充。

9. 批量人工优惠

模块 需求说明
基础表单 地区、商户、会员ID、存入金额、打码量、备注、APP端备注、参与层级、领取方式、保存。存入金额必填且必须大于0，并且不能大于后台配置的批量人工优惠单笔金额。
会员ID 支持输入多个会员ID，多个会员ID用英文逗号分隔。
参与层级 包含全部层级、默认层级、10雷、20雷、50雷、100雷、200雷、500雷、1000雷、5000雷、10000雷、50000雷、测试账号、不出款、刷子套利、无体验金等。
领取方式 自动领取、弹窗领取、充值后领取的点击交互与人工优惠 tab 完全一致，并按领取方式决定是否直接到账或等待玩家领取。
下载模板 下载 Excel：批量人工优惠会员ID模板 (1).xlsx；字段为会员ID、优惠金额、打码倍数、APP端备注、后台备注。
导入用户 导入弹窗仅包含导入方式、选择文件、参与层级，不展示执行配置；导入采用整批校验，存在任一失败原因则整批不入库，并在导入弹窗提示失败原因；校验全部通过后生成待执行记录。
开始执行 待执行记录点击开始执行，弹窗选择 APP端领取方式并展示对应执行配置；自动领取会在人工优惠记录直接生成已完成/已领取订单，并同步流入优惠赠送记录；弹窗领取或充值后领取先生成未领取信息。
作废 待执行记录支持作废，二次确认后状态变为已作废。原型可演示导入后待执行、开始执行后执行中/已完成、作废后已作废并隐藏作废按钮；真实状态是否前端同步展示以后端回传为准。

10. 批量优惠记录

字段/状态 需求说明
筛选条件 状态、赠送对象、日期、操作人，支持查询、导入、下载模板。
状态选项 仅保留全部、待执行、执行中、已完成、已作废；移除导入中、导入失败、已暂停。
列表字段 创建时间、订单号、赠送对象、查看会员、查看奖励配置、执行进度、状态、奖励过期时间、操作人、操作。
查看进度 打开查看进度弹窗，支持会员ID、领取状态筛选和刷新，展示会员执行明细与分页。
查看奖励配置 打开只读配置弹窗，展示导入方式、文件、参与层级和执行配置。
操作按钮 待执行显示开始执行、作废、导出数据；已完成显示查看进度、作废、导出数据；已作废仅保留导出数据。若后端不实时回传状态，前端不强制本地推算批量任务状态。

11. 人工优惠记录

区域 需求说明
筛选区 会员ID、操作状态、赠送对象、创建时间、是否开启加倍奖励、操作人、订单状态、领取方式、地区、商户、重置、查询。
下拉枚举 是否开启加倍奖励：全部/是/否；订单状态：全部/未领取/已领取/作废/过期/放弃；领取方式：全部/自动领取/弹窗领取/充值后领取；操作状态：全部/准备/运行中/暂停/已完成/作废/导入中/导入失败；赠送对象：全部/单人优惠/批量导入。
统计数据 记录总数、派发人数、已领取人数、未加倍人数、已加倍人数、充值金额总和、已领取总金额、已领取打码量、加倍领取金额总和。

创建时间 人工优惠或批量人工优惠批次创建时间。

已领取打码量 显示当前订单内已经领取人工优惠以及批量人工优惠金额(含加倍金额以及初始金额)的打码量。
后台备注 后台运营创建人工优惠或批量人工优惠时填写的备注内容。
操作人 创建或执行该订单的后台操作账号。
操作 根据记录状态展示可执行动作，例如作废、导出数据、查看进度；作废成功后隐藏作废按钮。
统计-记录总数 统计数据区域显示当前筛选条件下人工优惠以及批量人工优惠记录总数。
统计-派发人数 统计数据区域按当前筛选条件汇总已派发会员人数总和(不去重)。
统计-已领取人数 统计数据区域按当前筛选条件汇总已领取会员人数总和(不去重)。
统计-未加倍人数 统计数据区域按当前筛选条件汇总领取初始金额或未开启奖励加倍的会员人数总和(不去重)。
统计-已加倍人数 统计数据区域按当前筛选条件汇总已选择并成功领取加倍奖励的人数总和。
统计-充值金额总和 统计数据区域按当前筛选条件汇总关联充值订单充值金额。

15. 数据流转与状态

流程 状态/数据流转
人工存入 创建成功后直接完成账变，并进入人工存款记录。若存在赠送优惠，优惠部分按领取状态流入优惠赠送记录。
人工提出 创建成功后直接完成扣款账变，并进入人工提款记录。人工提出金额不受安全设置单笔金额上限限制。
人工优惠-自动领取 创建后直接到账，在人工优惠记录中创建一条已完成、已领取订单，同时流入人工提存记录的优惠赠送记录。
人工优惠-弹窗/充值后领取 创建后只在人工优惠记录中创建未领取订单；只有玩家成功领取后，才流入人工提存记录的优惠赠送记录。
批量人工优惠导入 导入后生成待执行批量记录，不在导入弹窗选择执行配置。
批量人工优惠执行 点击开始执行后选择领取方式和执行配置，确认后按对应配置执行；批量导入记录通过“查看会员”查看各会员领取情况。
批量人工优惠流转 自动领取的会员记录会在人工优惠记录直接生成已完成、已领取信息，并同步流入优惠赠送记录；弹窗领取、充值后领取的会员记录先保持未领取，玩家成功领取后再流入优惠赠送记录。
批量人工优惠状态 原型可演示导入后待执行/准备、开始执行后执行中/已完成、作废后已作废并隐藏作废按钮；真实状态是否同步给前端以后端接口回传为准。
客户端站内信-人工存入 人工存入创建成功并完成账变后，客户端消息中心生成存款成功站内信。
客户端站内信-人工提出 人工提出创建成功并完成扣款账变后，若后台选择发送邮件/站内信通知，则客户端消息中心生成扣款通知；若选择不发送，则不生成。
客户端站内信-人工优惠 人工优惠或批量人工优惠只有玩家成功领取后才生成优惠站内信；自动领取视为创建后立即领取成功。若有加倍，初始奖励领取成功发一次，加倍奖励成功领取后再发一次。
客户端弹窗领取 弹窗领取且未开启奖励加倍时，客户端首页展示初始奖励领取弹窗，领取成功后发站内信并完成后续记录流转；客户端保持在当前页面，不自动跳消息中心。
客户端按充值金额加倍领取 弹窗领取且开启按充值金额加倍时，初始奖励领取成功后先发站内信，但不自动跳消息中心，再展示后台加倍模板：固定倍数展示每档充值金额对应固定倍数，随机倍数展示每档充值金额对应最小/最大倍数范围；玩家继续加倍并完成充值条件后，再发一条加倍奖励站内信。
客户端充值后领取 充值后领取不先直接到账，客户端展示活动规则弹窗；玩家点击充值并满足后台配置充值条件后，仍需点击领取。只有领取成功后，才生成优惠站内信。
记录作废 仅改变当前行状态和操作按钮展示，不影响其他记录。

16. 开发实现要点

  • 所有 tab 切换仅做原型内前端交互，后台接口不在本期扩展。
  • 单笔保存必须依赖会员搜索成功状态，不应仅依赖输入框有值。
  • 批量导入与开始执行拆成两个阶段：导入阶段只选择对象，执行阶段再选择领取方式与执行配置。
  • 人工优惠、批量人工优惠、导入后开始执行弹窗的领取方式交互应复用同一套显隐规则。
  • 批量任务状态变化在原型中可演示为待执行、执行中、已完成、已作废；实际是否由前端即时更新，以后端状态回传能力为准。
  • 模板新增、查看、删除、校验逻辑保持一致；查看模板为只读状态。
  • 长表格需要横向滚动并设置合理列宽，避免订单号与状态字段挤压。
  • 本期原型中移除自动优惠、自动优惠统计 tab，避免评审误解为本期范围。
  • 人工提出不做后台单笔金额上限校验；安全设置页不新增人工提出单笔上限字段。
  • 客户端站内信文案由后台触发场景和金额参数生成，前端仅负责展示列表、未读红点、详情和弹窗状态。
  • 客户端领取弹窗金额、站内信金额、加倍提示倍率、加倍后站内信金额均由后台配置或领取结果动态传入；客户端不得写死 1.00、2x 等展示值。
  • 客户端站内信触发点必须以领取成功为准：自动领取等同于后台直接领取成功；弹窗领取和充值后领取在玩家点击领取成功后发信；有加倍时，初始奖励领取成功发一次，加倍奖励成功领取后再发一次。
  • 客户端领取成功或加倍奖励领取成功后，只生成站内信和页面提示，不强制跳转消息中心；用户通过个人中心站内信入口自行查看通知详情。
  • 客户端领取弹窗和加倍提示需要支持重复打开、关闭、领取成功、放弃加倍、继续充值等状态，避免页面刷新后状态丢失的真实实现需结合客户端缓存和后端领取状态接口设计。

AC-23 充值后领取场景展示充值条件弹窗；点击 Depositar Agora 进入充值页，满足后台配置条件后展示可领取状态；玩家点击领取成功后才生成优惠站内信；点击 Desistir 关闭弹窗并视为放弃。

  • 真实后端会员 ID 校验接口、返回字段和错误码需由研发与后端确认。
  • 人工优惠记录中“操作状态”和“订单状态”的最终枚举值需与后端数据字典对齐。
  • 奖励加倍模板删除后切换默认模板的影响范围需后端确认是否影响历史记录。
  • 批量任务开始执行后的进度刷新机制、失败重试策略和导出字段需接口设计时补充；前端是否本地推算状态，需以后端状态回传能力为准。

19. 边界场景补充

场景 建议规则
重复保存/重复点击 后台保存、开始执行、RECEBER 领取、Depositar Agora 充值提交均需做幂等处理。重复点击或接口重试不得重复账变、重复发放优惠、重复生成站内信。前端按钮应在请求中展示 loading 或禁用。
领取时状态变化 玩家打开弹窗后，如果后台记录被作废、过期、已领取或风控拦截，点击 RECEBER 时必须以后端最新状态为准；不可仅凭客户端弹窗状态发放。失败时固定提示“奖励已失效”，不生成站内信，不流入优惠赠送记录。
作废与领取并发 作废操作只能影响未领取/未执行完成的部分。若玩家已领取成功，后台作废不得回滚已完成账变；批量任务部分会员已领取时，作废应仅停止未领取/未执行会员，并保留已领取会员记录。
奖励过期 弹窗领取、充值后领取、加倍奖励均需以后端时间判断过期，客户端时间不可作为准入依据。过期后订单状态变为过期，玩家不可领取，不发站内信，不进入优惠赠送记录。
充值匹配 同一笔充值只匹配一条待领取或待加倍奖励。若同一会员存在多个待匹配奖励，按奖励发放时间正序优先匹配，避免同一笔充值重复触发多次发奖。
充值异常 充值失败、取消、超时、被冲正、被风控拒绝时，不应触发充值后领取或加倍奖励；已触发后如充值被撤销，是否追回优惠需后端风控规则另行定义。
加倍模板快照 优惠创建或批量执行时应保存加倍模板快照。后续模板被编辑、删除或切换默认模板，不应影响已创建订单的领取计算和查看详情。
随机倍数落库 按充值金额随机倍数时，最终随机到的实际倍数、期望倍数、充值档位、计算金额需随会员领取明细落库，便于客服查询、复核和报表统计。
金额精度与舍入 所有金额建议统一到后台币种精度，明确四舍五入/截断规则。金额校验需覆盖空值、0、负数、非数字、超后台上限、小数位超限、批量导入科学计数法等情况。
批量导入失败 批量导入采用整批校验。只要存在会员不存在、重复会员、金额不合法、层级不匹配、备注超长、超过后台上限等任一失败原因，则整批不入库，在导入弹窗直接提示失败原因；失败数据不录入批量优惠记录列表，也不生成待执行批次。
重复会员 同一批次内重复会员、不同批次同一会员同时存在多个待领取奖励时，允许奖励并存。客户端一次只展示一个领取弹窗，并按奖励发放时间正序排序；当前弹窗领取或关闭后，再展示下一条未领取且未过期奖励。
统计口径 人工优惠记录统计已声明人数不去重，研发实现需与表头提示一致。已领取人数、已加倍人数、未加倍人数、充值人数、已领取总金额、加倍领取金额总和均以成功账变/成功领取结果为准。
站内信补偿 站内信只在领取成功后生成；如果优惠账变成功但站内信发送失败，后台需补偿重发站内信，不影响已完成账变，且不能因站内信失败重复发放优惠。
权限与审计 人工存入、人工提出、人工优惠、批量执行、作废、安全设置金额上限调整均建议记录操作日志，包含操作人、时间、前后值、会员/批次、IP 或设备信息。
前端展示恢复 玩家刷新客户端、切换设备、重新登录后，未领取、可加倍、充值后待领取等状态应从后端重新拉取，避免仅依赖本地弹窗状态。
