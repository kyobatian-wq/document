## 1. 背景与目标

本需求围绕商户财务管理下的人工提存能力进行原型化补充，覆盖人工单笔存入、人工单笔提出、人工优惠、批量人工优惠、人工提存记录、人工优惠记录、客户端站内信与领取弹窗交互，并补充系统管理 / 安全设置中的金额上限配置。

目标是让运营人员在人工资金调整和优惠派发场景中，先校验会员信息，再按明确配置保存或执行，并让资金账变、优惠派发、玩家领取和记录流转路径清晰可追溯。

- 还原截图中的后台视觉和操作路径，作为评审与研发对齐基准。

- 明确单笔操作的会员 ID 校验、保存二次确认、成功/失败提示。

- 补齐人工优惠与批量人工优惠的领取方式、奖励加倍、模板管理、状态流转、查看会员、记录查询和客户端领取反馈。

- 本期不做自动优惠、自动优惠统计，对应 tab 在原型中直接移除。

## 4. 通用交互规则

| 规则 | 说明 |
| --- | --- |
| 会员 ID 校验 | 人工存入、人工提出、人工优惠等单笔操作必须先点击会员 ID 搜索按钮。只有成功读出会员信息后才允许保存。会员 ID 未输入或未匹配到对应 ID 时提示“请输入正确的会员ID”；保存时未完成正确会员校验时提示“数据信息不完整”。 |
| 正确 ID 演示 | 输入 123456 并点击搜索，展示账号类型、账号、所属地区、所属商户、会员余额、会员等级。 |
| 保存二次确认 | 点击保存后弹出确认框，例如“确认人工存入?”，确认后再执行保存。 |
| 后台金额上限 | 人工存入、人工优惠、批量人工优惠金额受系统管理 / 安全设置中的后台配置限制；人工存入金额不能大于“人工存入单笔金额”，人工优惠金额不能大于“人工优惠单笔金额”，批量人工优惠金额不能大于“批量人工优惠单笔金额”。人工提出本期不做单笔上限校验，仅校验金额必填且大于0。原型示例配置：人工存入单笔金额1001，人工优惠单笔金额100，批量人工优惠单笔金额100。 |
| 金额精度 | 人工存入、人工优惠、批量人工优惠中的存入金额支持输入两位小数；前后端均需限制最多两位小数，金额仍需大于0并满足对应后台上限。 |
| 赠送比例上限 | 人工存入的赠送比例最多 100%；前后端均需限制。后台交互中输入大于 100 的数值后，输入框自动修正为 100。 |
| 提现倍数取整 | 充值提现倍数、优惠提现倍数允许输入 0 或其他整数单位；前后端均需限制为整数。后台交互中输入小数后自动四舍五入为整数单位。 |
| 列表作废 | 点击作废弹出二次确认；确认后提示“作废成功”，当前行操作状态由“准备”改为“作废”，并隐藏该行作废按钮。 |
| 字段间距 | 列表中长订单号、操作状态、订单状态等字段需保留独立列宽，避免文本挤压或贴合。 |
| 赠送对象命名 | 所有列表中的“首存次日未充值用户”统一调整为“批量导入”。 |

| 弹窗领取-不开启奖励加倍 | 玩家进入客户端首页时展示领取弹窗，内容金额按后台配置的优惠金额动态展示，例如 Receber um bônus +R${配置金额}；点击 RECEBER 后领取成功并发送优惠领取成功站内信；客户端不自动跳转消息中心，玩家可自行从站内信入口查看。 |

| 弹窗领取-按充值金额固定倍数 | 先展示初始奖励领取弹窗；点击 RECEBER 后不立即生成优惠站内信，也不自动跳转消息中心，随后展示 Multiplier Rewards 加倍提示。提示内按后台加倍模板展示充值金额档位与固定倍数，例如“Depósito / múltiplo”两列；档位金额和倍数均由后台配置动态传入。充值金额仅用于判断是否命中对应档位；加倍计算基数为后台存入金额/优惠彩金金额，不是该笔充值本金。若玩家继续充值并成功领取加倍奖励，则按加倍后实际奖励金额发送一次优惠站内信；若玩家取消加倍福利并直接领取当前奖励，则按当前奖励金额发送一次优惠站内信；加倍场景全流程只发一次优惠站内信。 |
| 弹窗领取-按充值金额随机倍数 | 流程与固定倍数一致，但 Multiplier Rewards 中每个充值金额档位展示最小/最大随机倍数范围，例如“1,10 - 3x”；最终加倍倍数以后端实际计算结果为准。充值金额仅用于判断是否命中随机倍数档位；加倍计算基数为后台存入金额/优惠彩金金额，不是该笔充值本金。若玩家继续充值并成功领取加倍奖励，则按加倍后实际奖励金额发送一次优惠站内信；若玩家取消加倍福利并直接领取当前奖励，则按当前奖励金额发送一次优惠站内信；加倍场景全流程只发一次优惠站内信。 |
| 充值后领取-单笔充值 | 客户端首页展示单笔充值后领取弹窗，包含初始奖励金额、活动说明、单笔充值条件金额、Depositar Agora、Desistir。金额与充值条件由后台配置传入；点击 Depositar Agora 进入充值页，若未充值直接点击充值页返回按钮，则回到该充值后领取提示页。满足单笔充值条件后不直接发站内信，而是统一展示领取结果页，领取结果页显示该玩家本次可领取的优惠彩金金额；玩家点击 Reivindicar Bônus / 领取按钮后才视为领取成功，并生成优惠站内信、帐变和稽核记录，且不自动跳转消息中心。点击 Desistir 视为放弃，后台人工优惠记录订单状态更新为放弃。 |
| 充值后领取-累计充值 | 客户端首页展示累计充值后领取弹窗，包含初始奖励金额、活动说明、累计充值条件金额、Depositar Agora、Desistir。点击 Depositar Agora 进入充值页，若未充值直接点击充值页返回按钮，则回到该累计充值提示页。满足累计充值条件后不直接发站内信，而是统一展示领取结果页，领取结果页显示该玩家本次可领取的优惠彩金金额；玩家点击 Reivindicar Bônus / 领取按钮后才视为领取成功，并生成优惠站内信、帐变和稽核记录。首次点击 Desistir 不直接放弃，需展示累计充值确认提示；只有在确认提示中再次点击 Desistir，才结束该优惠并将后台人工优惠记录订单状态更新为放弃；若在确认提示中点击 Confirmar，则回到累计充值提示页并保留优惠。 |

## 16. 开发实现要点

- 所有 tab 切换仅做原型内前端交互，后台接口不在本期扩展。

- 单笔保存必须依赖会员搜索成功状态，不应仅依赖输入框有值；会员 ID 为空或未匹配时提示“请输入正确的会员ID”，保存时会员校验状态不完整时提示“数据信息不完整”。

- 存入金额字段需支持最多两位小数，前端输入和后端接口均需校验小数位、正数和后台金额上限。

- 人工存入赠送比例前端需在输入后将大于 100 的值自动修正为 100，后端保存接口仍需校验赠送比例不得超过 100%。

- 充值提现倍数、优惠提现倍数允许 0 和其他整数单位；前端输入小数时四舍五入为整数，后端保存接口仍需拒绝非整数倍数。

- 批量导入与开始执行拆成两个阶段：导入阶段只选择对象，执行阶段再选择领取方式与执行配置；导入弹窗本期仅支持批量导入，按条件导入需置灰不可选并标注“本期不做”。

- 人工优惠、批量人工优惠、导入后开始执行弹窗的领取方式交互应复用同一套显隐规则。

- 批量任务状态变化在原型中可演示为导入中、导入失败、准备、运行中、暂停、已完成、作废；暂停和继续执行需依赖后端接口确认成功后再更新状态，实际是否由前端即时更新，以后端状态回传能力为准。

- 模板新增、查看、删除、校验逻辑保持一致；查看模板为只读状态。

- 长表格需要横向滚动并设置合理列宽，避免订单号与状态字段挤压。

- 本期原型中移除自动优惠、自动优惠统计 tab，避免评审误解为本期范围。

- 人工提出不配置后台单笔金额上限字段，安全设置页不新增人工提出单笔上限；但人工提出必须做会员账户余额校验，提现金额大于账户余额时提示“账户余额不足”。

- 客户端站内信文案由后台触发场景和金额参数生成，前端仅负责展示列表、未读红点、详情和弹窗状态。

- 帐变与稽核对应表需作为本次需求的独立清单维护；人工存款无赠送时只生成人工充值，人工存款有赠送比例时本金计存款、赠送计优惠；人工优惠和批量人工优惠仅领取成功后写入帐变，未领取不写帐变。

- 客户端领取弹窗金额、站内信金额、加倍提示倍率、加倍后站内信金额均由后台配置或领取结果动态传入；客户端不得写死 1.00、2x 等展示值。奖励加倍的金额基数必须使用后台存入金额/优惠彩金金额，不能使用触发加倍的充值本金。

- 领取方式为弹窗领取且开启奖励加倍时，固定加倍倍数、按充值金额加倍的倍数区间值均允许输入不小于 1 且最多两位小数的倍数值；输入小于 1 点击保存时提示“加倍倍数不可小于1”。前后端保存接口均需执行同口径校验。

- 客户端站内信触发点必须以领取成功为准：自动领取等同于后台直接领取成功；弹窗领取在玩家点击领取成功后发信；充值后领取及需要充值触发的加倍奖励，在充值条件满足后需先展示领取结果页，玩家点击领取结果页按钮后才发信，并写入帐变和稽核记录；领取结果页未点击领取按钮前必须保持待领取，不得生成站内信、帐变或稽核记录；有加倍时，加倍完成后发一次，或取消加倍福利直接领取当前奖励发一次，加倍场景全流程只发一次优惠站内信。

- 客户端领取成功或加倍奖励领取成功后，只生成站内信和页面提示，不强制跳转消息中心；用户通过个人中心站内信入口自行查看通知详情。

- 客户端领取弹窗、加倍提示、充值后领取提示和领取结果页需要支持重复打开、关闭、领取成功、放弃加倍、继续充值、充值页未充值返回、累计充值二次放弃确认等状态，避免页面刷新后状态丢失的真实实现需结合客户端缓存和后端领取状态接口设计。

## 18. 待确认问题

- 真实后端会员 ID 校验接口、返回字段和错误码需由研发与后端确认。

- 人工优惠记录中“操作状态”和“订单状态”的最终枚举值需与后端数据字典对齐。

- 奖励加倍模板删除后的历史订单按已保存模板快照展示和计算，不受模板后续修改、删除或默认模板切换影响。

- 批量任务开始执行后的进度刷新机制、暂停/继续执行接口、失败重试策略、查看会员/查看奖励配置接口和导出字段需接口设计时补充；前端是否本地推算状态，需以后端状态回传能力为准。

## 19. 边界场景补充

| 场景 | 建议规则 |
| --- | --- |
| 重复保存/重复点击 | 后台保存、开始执行、RECEBER 领取、Depositar Agora 充值提交均需做幂等处理。重复点击或接口重试不得重复账变、重复发放优惠、重复生成站内信。前端按钮应在请求中展示 loading 或禁用。 |
| 领取时状态变化 | 玩家打开弹窗后，如果后台记录被作废、过期、已领取或风控拦截，点击 RECEBER 时必须以后端最新状态为准；不可仅凭客户端弹窗状态发放。失败时固定提示“奖励已失效”，不生成站内信，不流入优惠赠送记录。 |
| 作废与领取并发 | 作废操作只能影响未领取/未执行完成的部分。若玩家已领取成功，后台作废不得回滚已完成账变；批量任务部分会员已领取时，作废应仅停止未领取/未执行会员，并保留已领取会员记录。 |
| 奖励过期 | 弹窗领取、充值后领取、加倍奖励均需以后端时间判断过期，客户端时间不可作为准入依据。过期后订单状态变为过期，玩家不可领取，不发站内信，不进入优惠赠送记录。 |
| 充值匹配 | 同一笔充值只匹配一条待领取或待加倍奖励。若同一会员存在多个待匹配奖励，按奖励发放时间正序优先匹配，避免同一笔充值重复触发多次发奖。 |
| 充值异常 | 充值失败、取消、超时、被冲正、被风控拒绝时，不应触发充值后领取或加倍奖励；从提示页进入充值页后未充值直接返回，只恢复原提示页，不改变订单状态；已触发后如充值被撤销，是否追回优惠需后端风控规则另行定义。 |
| 加倍模板快照 | 优惠创建或批量执行时应保存加倍模板快照。后续模板被编辑、删除或切换默认模板，不应影响已创建订单的领取计算和查看详情。 |
| 随机倍数落库 | 按充值金额随机倍数时，最终随机到的实际倍数、期望倍数、充值档位、计算金额需随会员领取明细落库，便于客服查询、复核和报表统计。计算金额需明确区分触发充值金额与被加倍的优惠彩金金额。随机倍数的最小值、最大值、期望值均需按不小于 1 且最多两位小数保存。 |
| 金额精度与舍入 | 存入金额最多支持两位小数；所有金额建议统一到后台币种精度，明确四舍五入/截断规则。金额校验需覆盖空值、0、负数、非数字、超后台上限、小数位超限、批量导入科学计数法等情况。赠送比例不得超过 100%；充值提现倍数、优惠提现倍数可为 0 或其他整数，小数输入需四舍五入并按整数入库。 |
| 批量导入失败 | 批量导入采用整批校验。只要存在会员不存在、重复会员、金额不合法、层级不匹配、备注超长、超过后台上限等任一失败原因，则整批不生成可执行批次；批量优惠记录可生成导入失败状态记录，用于查看/导出失败结果。 |
| 重复会员 | 同一批次内重复会员、不同批次同一会员同时存在多个待领取奖励时，允许奖励并存。客户端一次只展示一个领取弹窗，并按后台创建时间正序排序；当前弹窗领取、点击 Continue reivindicando、完成最终 Desistir 放弃、作废、过期或后端判定失效后，再展示下一条仍有效的待处理奖励。 |
| 统计口径 | 人工优惠记录统计已声明人数不去重，研发实现需与表头提示一致。已领取人数、已加倍人数、未加倍人数、充值人数、已领取总金额、加倍领取金额总和均以成功账变/成功领取结果为准。 |
| 站内信补偿 | 站内信只在领取成功后生成；如果优惠账变成功但站内信发送失败，后台需补偿重发站内信，不影响已完成账变，且不能因站内信失败重复发放优惠。 |
| 权限与审计 | 人工存入、人工提出、人工优惠、批量执行、作废、安全设置金额上限调整均建议记录操作日志，包含操作人、时间、前后值、会员/批次、IP 或设备信息。 |
| 前端展示恢复 | 玩家刷新客户端、切换设备、重新登录后，未领取、可加倍、充值后待领取等状态应从后端重新拉取，避免仅依赖本地弹窗状态。 |
