1. 需求目标

在设备关联查询结果中同时展示注册设备号和登录设备号，准确识别同一设备关联的会员账号，便于核对会员ID与设备信息。

2. 已确认内容

需求项规则说明
入口范围同时覆盖个人资料中「最后登录」「注册IP」区域的「设备关联」入口，点击后打开「关系查询」弹窗。
登录设备关联按发起查询会员的当前登录设备号，查询当前登录设备号相同的关联会员。
注册设备关联按发起查询会员的注册设备号，查询注册设备号相同的关联会员。
新增：注册设备号展示当前行会员注册时对应的设备号。会员后续更换登录设备时，此字段仍展示注册设备信息。
新增：登录设备号展示当前行会员最近一次登录使用的设备号，随会员登录设备改变而更新。
字段对应关系两列均为只读展示，必须与同一行会员ID准确对应。注册关联中各会员的登录设备号可以不同；登录关联中各会员的注册设备号可以不同。
统计字段保留「有效投注」，补充「游戏输赢」「充值总额」「提现总额」，展示当前行会员对应的数据；游戏输赢为负数时以红色展示。
字段顺序与展示「注册IP」后依次展示「注册设备号」「登录设备号」「有效投注」「游戏输赢」「充值总额」「提现总额」。关系查询弹窗拉宽，压缩列宽和单元格间距；表头、渠道、IP、设备号等长内容允许换行，完整平铺展示全部字段，无需左右滑动。
重复设备关联账号同一设备关联多个会员时，分别展示各会员ID及其两个设备号，不得因设备号重复而合并、遗漏或错配不同会员。设备号不能用作会员行的唯一标识。
会员资料入口关系查询结果中的会员ID保留点击功能，点击后打开该会员的个人资料；弹窗内的会员ID、会员账号、设备号等资料均取目标会员数据。
权限地图本次不涉及权限地图调整，沿用现有权限规则。
子账号操作日志本次不涉及子账号操作日志调整，沿用现有日志规则。

3. 交互流程

个人资料 → 设备关联（登录 / 注册）→ 关系查询 → 点击会员ID → 目标会员个人资料

关闭目标会员个人资料后，返回原关系查询结果。本原型保留查询条件、当前页及滚动位置，方便连续核对会员。

4. 原型演示约定 / 建议方案

以下为可评审的演示处理，不作为新增的已确认业务规则：

场景原型处理
布局与标识设备号字段以「新增」标记，高亮本次查询匹配的设备号；完整展示设备号，空间不足时换行。手机等窄屏下，同一会员的字段按顺序纵向展示，无需左右滑动。
查询与分页会员ID采用精确匹配，渠道可筛选，点击「查询」后生效；「重置」清空附加条件。地区、商户使用当前演示数据范围，翻页后仍保持设备关联范围。
去重与本人演示数据按会员ID一人一行，并包含发起查询的会员本人；生产是否排除本人、现有去重方式沿用既有规则，需联调核对。
无设备号 / 无结果缺失设备号展示「-」，对应入口不可点击；不将多个缺失设备号识别为同一设备。无查询结果展示「暂无数据」。
资料弹窗返回目标资料在关系查询之上打开，关闭后保留原结果；弹窗可按 Esc 逐层关闭。

5. 验收要点

  1. 两个设备关联入口均展示注册设备号、登录设备号，列值与会员ID逐行对应。
  2. 同一设备对应多个会员时，完整展示关联会员；不同设备的会员不混入当前查询结果。
  3. 注册关联允许登录设备不同，登录关联允许注册设备不同。
  4. 更换登录设备后，个人资料及关系查询中的登录设备号更新，注册设备号保持注册时的值。
  5. 点击不同会员ID时展示对应个人资料，关闭后可继续查看原查询结果。
  6. 有效投注、游戏输赢、充值总额、提现总额与对应会员一致；负数输赢显示红色。长内容换行后不重叠、不省略，桌面端全部列无需左右滑动。
