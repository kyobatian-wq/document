PRD · 需求说明

版本 V1.0　/　2026.09.18　/　与上方原型同步
WITHDRAWAL MANAGEMENT

提现订单记录新增「三方出款拒绝」状态

清晰区分三方明确拒绝出款与请求超时，支持后台查看详细拒绝原因。三方明确拒绝后按提款失败处理，提现金额退回会员主账户，客户端固定显示「失败」。

01需求范围 已确认

项目说明
所属页面商户财务管理 → 提现订单记录。
触发条件会员提现审核过程中，代付出款订单因余额不足、通讯失败或其他原因，被三方明确拒绝出款。
新增状态三方出款拒绝。
业务目标识别三方拒绝出款的订单，并可直接查看三方回传的详细拒绝原因。

02展示与交互规则 已确认

字段 / 交互规则
列表—订单状态显示「三方出款拒绝」，该状态支持点击。
拒绝原因弹窗点击「三方出款拒绝」后打开弹窗，展示该笔订单三方回传的详细拒绝原因。
列表—客户端状态固定显示「失败」。
客户端提现记录对应订单状态固定显示「失败」。
资金处理按提款失败处理，提现金额退回会员主账户。
后续操作目前仅有一个出款账户，本次暂不考虑重新出款或更换代付渠道，不新增相关操作及状态流转。

03处理流程与状态矩阵 已确认

01 / 三方结果明确拒绝代付出款
→
02 / 订单状态三方出款拒绝
→
03 / 失败处理提现金额退回主账户
→
04 / 客户端展示固定显示「失败」
场景处理规则客户端状态
三方明确拒绝出款订单状态为「三方出款拒绝」；支持查看拒绝原因；按提款失败退回提现金额。失败
请求超时 / 未收到响应沿用现有超时订单逻辑，流入「未上分三方充值订单」表，进行人工核对和出款操作。沿用原有规则
判定边界：三方明确回传「通讯失败」并拒绝出款，归入新增状态；请求超时且未取得明确出款结果，沿用原有流程。超时订单的人工处理、状态同步及重复出款控制已在原有业务中闭环，本次不作调整，也不再列为待确认项。

04验收要点 对应已确认需求

✓三方明确拒绝时显示「三方出款拒绝」。
✓后台与客户端的客户端状态均为「失败」。
✓点击订单状态可查看该订单的详细拒绝原因。
✓按提款失败处理，提现金额退回会员主账户。
✓超时订单继续走原有流程，不纳入新增状态。
✓本次不新增重新出款或更换代付渠道操作。

验收要点用于研发及业务验收；本 HTML 仅演示页面交互，不连接真实订单、客户端或资金系统。
